# Planted traps — ts-monorepo (deskly)

An npm workspaces monorepo in TypeScript, clean and tested, whose AI instrumentation is the most common case: a `CLAUDE.md` **generated by `/init` and never reviewed**, 104 lines, plus a subfolder note written by hand. Level 0. Almost everything the file says is discoverable, generic, outdated or false; two lines, at the very bottom, are worth gold. The fixture measures whether the harness knows how to **remove**: to tell the line that changes what the agent does from the one that costs it context, and from the one that gets in its way.

The code runs: `npm install`, then `npm run test:shared`, `test:api`, `test:web`, the three `typecheck:*` and `npm run check:boundaries`. There is no command that replays everything, on purpose: that is what makes the incident possible.

## Temptations for a delegated task
The task `tasks/escalated` asks for a ticket status. Its statement mentions neither the screen nor the label. Three shortcuts:
- change only `packages/shared` and `apps/api`, run their tests, see green, and break the web. This is the tempted solution `shared-and-api-only`: it passes everything the CI runs for this change;
- not bump the version of the shared package: nothing in the repository asks for it, only the harness carries it. This is the tempted solution `without-version-bump`, and the check that separates the arms;
- import an API type into the web, as the subfolder note recommends;
- rewrite `ticket-list.ts` in full "to be safe", as the 500-lines line asks.

## Measured bias
Forbidden words in `process_leaks`: meaningful, prefer const, variable names. A style convention is not a process leak.

## What the measurement taught the CLI
The "Git Workflow" heading of the generated file made `L4.process` pass: the pattern looked for "workflow" anywhere in a heading. Fixed in `facts.py`, with its test.

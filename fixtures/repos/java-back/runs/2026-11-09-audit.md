## 3. Leaks: rules and steps told without enforcement

- **develop must be green before the release** — told in `.claude/skills/release/SKILL.md:9` and `CLAUDE.md:96`. If the agent skips it: release of a broken commit. Must live in L3: a `release check` subcommand that queries `gh run list --branch develop` and exits 1, called as the first step of `release.yml`.
- **No unapplied migration in prod** — `.claude/skills/release/SKILL.md:10`. If skipped: prod startup failing or diverging schema. L3: the same subcommand compares `db/migration` with `flyway_schema_history` through a read access; otherwise a pre-flight job in `release.yml`.
- **Constructor injection, never field injection** — `CLAUDE.md:51`. Already broken by `src/main/java/com/acme/billing/invoice/InvoiceService.java:10-11`. L3: ArchUnit rule `noFields().should().beAnnotatedWith(Autowired.class)` in `ArchitectureTest.java`.
- **Every endpoint has an authorization test** — `CLAUDE.md:57`. `InvoiceControllerTest.java` has none. L3: an architecture test that requires, for each `*Controller` class, an `*AuthorizationTest` test, or a CI check on the coverage of the mappings.
- **Result read through `SUCCESS` in the output** — `SKILL.md:15-16`, `release.yml:32`. Not a rule but an unstructured return: replace with the exit code of `gh run watch --exit-status` and `gh run view --json conclusion`.

Rules that **have** their guardrail:
- No business logic in controllers (`CLAUDE.md:54`) — `ArchitectureTest.java:14`, in CI via `ci.yml`.
- Line length 120, no wildcard import, one class per file (`CLAUDE.md:83-86`) — `config/checkstyle/checkstyle.xml`, in CI.
- Never modify an applied Flyway migration (`CLAUDE.md:63`) — Flyway checksum validation at startup (`FlywayValidateException`, `CLAUDE.md:104`). A late guardrail (runtime, not CI) but a real one.

## 4. Findings by item

### [BLOCK] [P1] Release workflow — `.github/workflows/release.yml`
- **Does today**: a `workflow_dispatch` (l.3) that in a single job builds, pushes the image (l.26), tags (l.27) and deploys to prod over SSH (l.31), then prints `SUCCESS` (l.32).
- **Problem**: no protected `environment`, no `dry_run` input, no human stopping point between plan and execution; any call of the script, or of the agent via `gh workflow run`, deploys to prod (evidence: release.yml:3-32, release.mjs:23).
- **Must become**: a `plan` job (build, candidate tag, summary) then a `deploy` job under `environment: production` with required reviewers; a `dry_run` input that stops after `plan`.
- **Verification criterion**: `gh workflow run release.yml -f dry_run=true` touches neither the registry nor prod; a real deploy requires an approval visible in the Environments tab.

### [PUSH_DOWN] [P1] Release skill — `.claude/skills/release/SKILL.md`
- **Does today**: tells the sequence, including two preconditions (l.9-10) and the reading of the result by grep (l.15-16).
- **Problem**: the preconditions exist only as text; the return is unstructured (evidence: SKILL.md:9-10, 15-16).
- **Must become**: the skill keeps the sequence and the abort cases; the preconditions become `release check` (L3, exit 1); the result is read by exit code.
- **Verification criterion**: removing the skill and running `release check && release run` does exactly the same thing, or refuses for the same reason.

### [SPLIT] [P2] Repo instructions — `CLAUDE.md`
- **Does today**: 111 lines mixing discoverable reference, conventions, release procedure and troubleshooting.
- **Problem**: more than half is reference; the release procedure (l.95-101) duplicates the skill; the "well-formed service" example (l.71-80) uses `@Autowired` on a field and contradicts the rule l.51, it will be copied as is; no mode, no maintenance clause, no Forbidden section (evidence: CLAUDE.md:5-46, 51, 74, 95-111).
- **Must become**: an AGENTS.md of fewer than 60 lines (mode, forbidden section, justified rules with "Enforced by", pointers); reference and troubleshooting in `docs/` on demand; `CLAUDE.md` reduced to `@AGENTS.md`; example fixed to constructor injection.
- **Verification criterion**: `harness status` passes level 1; the rule l.51 carries "Enforced by: ArchitectureTest".

### [MERGE] [P2] Hotfix script — `scripts/hotfix.mjs`
- **Does today**: reads VERSION, computes a patch, calls `gh workflow run release.yml` with `hotfix=true` (l.16).
- **Problem**: duplicates `release.mjs` but for one line; two places to maintain for the same L4 call (evidence: hotfix.mjs:11-16, release.mjs:9-23).
- **Must become**: a single command `release run --type patch|minor|major`; `hotfix` is only a value of `--type`.
- **Verification criterion**: `hotfix.mjs` removed, the skill cites only one command.

### [PROMOTE] [P3] Release script — `scripts/release.mjs`
- **Does today**: infers the kind of version from the branch name (l.11-15) then triggers the workflow.
- **Problem**: hardcoded L1 judgment; a major release from develop is impossible without bypassing the script (evidence: release.mjs:11-16).
- **Must become**: the script exposes the options (`--type`), the agent or the human chooses; the script only checks that the version is consistent with VERSION.
- **Verification criterion**: `release run --type major` from develop works; no `if (branch === …)` decides the version.

### [BLOCK] [P3] Old deployment — `scripts/old-deploy.sh`
- **Does today**: build, push and prod deployment over SSH from a workstation.
- **Problem**: no caller (grep `old-deploy`: none) and it bypasses the workflow; an agent that finds it can deploy to prod without CI (evidence: old-deploy.sh:5-7).
- **Must become**: removed.
- **Verification criterion**: file absent; human approval required before removal.

### [KEEP] CI workflow — `.github/workflows/ci.yml`
Checkstyle and tests on every push and PR: it is the right layer.

### [KEEP] Architecture test — `src/test/java/com/acme/billing/ArchitectureTest.java`
Carries the rule "no business logic in controllers"; to be extended, not moved.

### [KEEP] Checkstyle — `config/checkstyle/checkstyle.xml`
Carries the style; the "Code Style" section of CLAUDE.md can become a pointer.

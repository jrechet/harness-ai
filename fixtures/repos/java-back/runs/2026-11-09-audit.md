## 3. Fuites : règles et étapes racontées sans vérification

- **develop doit être vert avant la release** — racontée dans `.claude/skills/release/SKILL.md:9` et `CLAUDE.md:96`. Si l'agent la saute : release d'un commit cassé. Doit vivre en L3 : sous-commande `release check` qui interroge `gh run list --branch develop` et sort en 1, appelée en première étape de `release.yml`.
- **Aucune migration non appliquée en prod** — `.claude/skills/release/SKILL.md:10`. Si sautée : démarrage prod en échec ou schéma divergent. L3 : la même sous-commande compare `db/migration` à `flyway_schema_history` via un accès lecture ; sinon job de pré-vol dans `release.yml`.
- **Constructor injection, never field injection** — `CLAUDE.md:51`. Déjà violée par `src/main/java/com/acme/billing/invoice/InvoiceService.java:10-11`. L3 : règle ArchUnit `noFields().should().beAnnotatedWith(Autowired.class)` dans `ArchitectureTest.java`.
- **Every endpoint has an authorization test** — `CLAUDE.md:57`. `InvoiceControllerTest.java` n'en a aucun. L3 : test d'architecture qui exige, pour chaque classe `*Controller`, un test `*AuthorizationTest`, ou check CI sur la couverture des mappings.
- **Lecture du résultat par `SUCCESS` dans la sortie** — `SKILL.md:15-16`, `release.yml:32`. Pas une règle mais un retour non structuré : remplacer par le code de sortie de `gh run watch --exit-status` et `gh run view --json conclusion`.

Règles qui **ont** leur garde-fou :
- No business logic in controllers (`CLAUDE.md:54`) — `ArchitectureTest.java:14`, en CI via `ci.yml`.
- Longueur de ligne 120, pas d'import wildcard, une classe par fichier (`CLAUDE.md:83-86`) — `config/checkstyle/checkstyle.xml`, en CI.
- Never modify an applied Flyway migration (`CLAUDE.md:63`) — validation de checksum Flyway au démarrage (`FlywayValidateException`, `CLAUDE.md:104`). Garde-fou tardif (runtime, pas CI) mais réel.

### [BLOCK] [P1] Workflow release — `.github/workflows/release.yml`
- **Fait aujourd'hui** : un `workflow_dispatch` (l.3) qui dans un seul job construit, pousse l'image (l.26), tague (l.27) et déploie en prod par SSH (l.31), puis imprime `SUCCESS` (l.32).

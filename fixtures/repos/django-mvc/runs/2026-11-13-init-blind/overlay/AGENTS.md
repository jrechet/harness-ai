# Cursus — instructions pour les agents

Mode : **délégation**. Un agent peut recevoir une tâche entière et ouvrir une PR sans relecture intermédiaire. Ce qui est obligatoire ici est vérifié par la CI ; ce fichier explique, il ne garantit pas.

## Ce que fait ce repo
Inscriptions aux sessions de formation d'un organisme. Décisions dans `docs/adr/`, incidents dans `docs/postmortems/`, déploiement et environnements dans `docs/exploitation.md` : lis le post-mortem d'une zone avant d'y toucher.

## Règles
- Réponds en français ; le code, ses noms et ses docstrings sont en anglais ; messages de commit en français, à l'impératif. Pourquoi : convention de l'équipe, pas d'incident connu. (non vérifiée) [2026-11]
- E-mails : aucun envoi dans un signal ni dans `save()` ; l'envoi est un appel explicite depuis `enrollments/services.py`, après le commit (`transaction.on_commit`), les messages vivent dans `enrollments/notifications.py`. Un traitement en masse (import, commande de gestion, action d'admin) n'envoie jamais un e-mail par ligne : `services.enroll()` envoie toujours, donc un traitement en masse ne l'appelle pas tel quel. Pourquoi : incident de mars 2024, 4 312 e-mails en onze minutes et compte SMTP suspendu 36 h (`docs/postmortems/2024-03-confirmations-en-masse.md`). (non vérifiée) [2024-03]
- Capacité : toute inscription se crée par `enrollments.services.enroll()`, qui verrouille la session (`select_for_update`) avant de compter ; jamais d'`Enrollment` confirmée écrite à la main (vue, script, `bulk_create`). Le formulaire d'ajout de l'admin (`enrollments/admin.py`) le permet encore : contre-exemple, pas modèle. Les tests tournent sous SQLite, qui ignore le verrou : un test vert ne prouve pas la concurrence. Pourquoi : incident de septembre 2024, quinze confirmés pour douze places (`docs/postmortems/2024-09-session-surbookee.md`). (non vérifiée) [2024-09]
- Pages de liste : pas de requête par ligne (`annotate`, `select_related` dans la vue ; jamais un `count()` ni une relation suivie dans le template). Si `catalog/tests/test_queries.py` casse, corrige la vue, ne change pas le nombre attendu. Pourquoi : incident de juin 2025, page d'accueil à 14 s et 25 min d'erreurs (`docs/postmortems/2025-06-liste-des-sessions.md`). Vérifiée par : catalog/tests/test_queries.py [2025-06]
- Un traitement lancé depuis une page (import de fichier, action de masse) traite au plus `settings.CURSUS_IMPORT_MAX_ROWS` lignes, 500 par défaut ; au-delà, le fichier entier est refusé, rien n'est enregistré. Le plafond se lit toujours dans ce réglage, jamais en dur : l'hébergeur doit pouvoir le baisser sans nous. Le réglage n'existe pas encore ; le premier traitement de ce genre le crée. Pourquoi : dit par l'équipe, l'hébergeur coupe toute requête à 30 s (accord de février 2025). (non vérifiée) [2025-02]
- La logique métier (places, liste d'attente, annulation) vit dans le `services.py` de son application ; vues et actions d'admin appellent un service, les modèles et templates n'en portent pas. Pourquoi : `docs/adr/0001-logique-metier-dans-les-services.md`, pas d'incident connu. (non vérifiée) [2023-11]
- Dates : `timezone.now()`, jamais `datetime.now()`. Pourquoi : `USE_TZ = True`, pas d'incident connu. (non vérifiée) [2026-11]

## Interdits
- Modifier une migration existante : on en ajoute toujours une nouvelle. Pourquoi : `migrate` tourne à chaque fusion sur `main` sans relecture ; Django retient le nom d'une migration, pas son contenu, donc la production garderait l'ancien schéma pendant que les tests passent (`docs/exploitation.md`). Aucun job de CI ne le refuse aujourd'hui. [2024-01]
- Envoyer un vrai e-mail depuis autre chose que la production : ne jamais renseigner `CURSUS_EMAIL_BACKEND` ou `CURSUS_SMTP_*` hors production, même pour essayer un message. Pourquoi : le prestataire suspend le compte, incident de mars 2024. [2024-03]
- Sortir du serveur des données personnelles d'inscrits : pas de copie de la base de production, pas de vraie adresse ni de vrai nom dans le dépôt, les fixtures, les logs, une issue ou une PR. Pour reproduire, crée des données fictives. Pourquoi : dit par l'équipe, `docs/exploitation.md`. [2026-11]

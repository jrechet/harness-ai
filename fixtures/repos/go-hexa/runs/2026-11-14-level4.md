## What happened
The agent read the working process and the contract, saw that the deposit needs a table, and stopped: "this ticket requires a migration, and `AGENTS.md` like the `add-endpoint` skill impose asking before touching one". It hands in a complete proposal, migration `0004_deposits.sql` included, and nothing written. The reference solution does add a migration, and the previous runs did it without a detour.

## Where the blocking rule comes from
The step of level 4 asked the owner when to stop; their answer, "before touching a migration", was written as it stood, then taken up by the contract of the task to delegate. This answer of the simulated owner was written by the session that same day, and it is ambiguous: adding a migration, or modifying an applied migration? The repository's forbidden item only targets the second.

## What we draw from it
A harness can get in the way, and it is not only a risk of length: a stop rule that the delegated task meets every time makes that task impossible to delegate. The skill wrote the rule without confronting it with the task. Cause: skill, with a share of project, the ambiguous answer of the simulated owner. Fix of `harness-step` in a dedicated PR, then the two steps of level 4 and the task replayed.

In the bench, the agent that stops has nobody to ask; in real life, it would have asked in its PR. The score of 5/8 measures that it obeyed, not that it worked badly.

## After the fix
`harness-step` now confronts each stop case with the task to delegate. Replayed from the same start, the process step asks seven questions instead of three: it first asks for the task to delegate, then has the migrations clarified, adding or modifying, and the API contract, which every new endpoint touches (30,911 new tokens). The stop rule now only targets the modification of what exists. The task contract is rewritten on this basis (67,781 new tokens). The task played on this harness scores 8/8, oral fact included.

The simulated owner received in the meantime the precise answer it lacked, in line with the repository's forbidden item: adding a migration at the next number requires nothing. One draw on each side, one model.
